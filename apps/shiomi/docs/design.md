# 潮見とひかり野線 設計書

架空の港町「潮見」と、潮見台から山ノ口まで走る「ひかり野線」で、電車とトラックを運転する 3D のゲームです。この文書は、作りを直す人・足す人のための設計のまとめです。操作と遊び方は [README](../README.md) にあります。

## 1. 目的と範囲

- PC とスマホのブラウザで、同じ世界の中の電車とトラックを運転できるようにする。
- 電車：3 路線（ひかり野線・あおば線・さざなみ線）と貨物列車。時刻表・信号と連動・ATS・制限速度・踏切・ほかの列車。区間ごとのチェックポイントと採点。
- トラック：連結車（トラクター＋40ft シャーシ）と単車（12ft）。スマホの傾きでハンドル、クレーンでの積み込み、港町の道路と道案内。
- 2 つは荷物でつながる：トラックで潮見貨物駅に運んだ 12ft コンテナを貨物列車が山ノ口へ運び、帰りの列車が持ち帰った荷物がトラックの依頼になる。
- 名前の会社・町・路線はすべて架空。

### 1.1 段階
| 段階 | 中身 | 状態 |
|---|---|---|
| 1 | 2 つのゲームを 1 つの作品にする | 済み |
| 2 | 港町をひかり野線の世界の中に置く（トラックから走る電車が見える） | 済み |
| 3 | 潮見貨物駅を本線につなぎ、トラックと機関車を乗り換えられるようにする。荷物の記録を端末の中だけで動かす（連携コードをなくす） | これから |
| 4 | 山ノ口まで道路を通す | これから |

## 2. 全体の作り

```
ブラウザ（three.js）
  ├─ src/main.ts … ?mode=train / ?mode=truck で乗り物を選び、その画面とプログラムを読み込む
  ├─ src/train/ … 電車（運転の計算・路線網と連動・世界の 3D・運転台・音）
  ├─ src/truck/ … トラック（車の動き・クレーン・道路網・町の 3D・傾きの入力）
  ├─ src/world/ … 2 つの世界を重ねる（港町の置き場所、トラックに乗っている間の鉄道）
  ├─ localStorage：連携コード・傾きの感度
  └─ このアプリの Worker（/shiomi/api/*）… 荷物の記録置き場（D1）
```

- 公開は Cloudflare Workers。作品 wiki の入口の Worker が `/shiomi/*` をこのアプリへ渡す。D1 は入口で `TRUCK_DB` を `DB` として渡す。前の公開先の `/train-sim/` と `/truck/` は `/shiomi/` へ移る。
- 運転の計算（`train/sim.ts`・`truck/sim/*`・`truck/world/roadnet.ts`）は画面に依存しない純粋な計算にして、単体テストで確かめる。

## 3. ファイルと役割

### 3.1 電車（`src/train/`）

| `route.ts` | 路線のデータ：中心線（曲率と勾配から作る）・駅と時刻・制限・信号・汽笛の位置・踏切 |

| `net/network.ts` | 路線網：あおば線（平面交差・分岐器で合流）、さざなみ線（高架） |
| `net/interlock.ts` | 連動：平面交差・合流・同じ線路を 2 本の列車が同時に使わないよう、進路を渡す（早い者勝ち） |
| `ai.ts` | 自動運転（ほかの路線の列車とテスト用） |
| `checkpoints.ts` | チェックポイント：区間ごとの「ここでこの操作」 |

| `world/*` | 線路・架線・信号・駅・橋・トンネル・踏切、地形、町並み、景色（木・草・岩）、海と川 |
| `post.ts`・`perf.ts` | 画面の後処理（GTAO・光のにじみなど）と、画質の自動調整 |

## 4. データ

### 4.1 路線
| 路線 | 駅 | 特徴 |
|---|---|---|
| ひかり野線 | 潮見台・浜田・稲穂・山ノ口（5.8 km） | 海辺から田んぼ・川・トンネルを抜けて山あいへ |
| あおば線 | 青葉・浜田・稲穂 | 浜田の手前でひかり野線と平面交差、分岐器で合流して稲穂まで乗り入れる |
| さざなみ線 | 東浜・浜田・西浜 | 町の上の高架線。浜田のホームの真上でほかの 2 路線をまたぐ |

### 4.2 荷物の記録（D1）
- `links`（連携コード 8 文字・作った時刻・呼び出しの回数）、`boxes`（コンテナ：番号・中身・重さ・場所・行き先）、`throttle`（使いすぎの制限）。
- コンテナの場所：工場 → トラック → 潮見貨物駅 → 貨物列車で山ノ口へ → 届いた。帰りの列車は山の荷物（木材・米など）を持ち帰る。
- 連携コードは見まちがえやすい `0 O 1 I` を使わない。1 つのコードで持てるのは 300 個まで。

### 4.3 端末に覚えるもの（localStorage）
| キー | 中身 |
|---|---|
| `trainsim.link` | 電車の画面の連携コード |
| `truck.link` | トラックの画面の連携コード |
| `truck.sens` | 傾きの感度 |

## 5. 主な仕組み

### 5.1 電車の運転と採点
- 1 区間ごとに、停止位置の誤差・到着と発車の時刻の誤差・乗り心地・ボーナスと減点で採点する。合計を満点（区間の数 × 100）で割り、S（95% 以上）・A・B・C・D。
- 出発信号は発車 10 秒前まで赤。制限を大きく超えると ATS が働く。
- 出発駅と到着駅を選べる（到着駅は出発駅より先）。

### 5.2 連動
- 平面交差・合流などの区間ごとに、列車が手前（950 m 以内）に来て発車できる状態なら、空いていれば進路を渡す。最後尾が抜けたら返す。進路を持たない列車の信号は赤。

### 5.3 トラック
- 依頼：港の 40ft（クレーンで自分で積む）→ ミドリ物流センター、潮見精機の 12ft → 潮見貨物駅、駅に届いた 12ft → 町の届け先（届け先ごとに 2 個まで）。
- 傾きのハンドル：重力の向きの、画面の面の中での回り方を見る。「まっすぐ」を合わせた向きとの角度だけを使うので、景色は水平のまま。
- 傾きのセンサーは https のページでしか使えない。

### 5.4 画質の自動調整
- 6 段（画素の比・GTAO・光のにじみ・影の大きさと距離・草と木の数）。はじめはスマホ 3 段目、PC 1 段目。
- 重いコマが続くと段を下げる。60 FPS がしばらく続いたら 1 段上げて試し、落ちた段はしばらく試さない。段を変えた直後の 2 秒は動かさない。

## 6. サーバー（Worker）

| 道 | 働き |
|---|---|
| `POST /api/link` | 連携コードを作る |
| `GET /api/link?code=` | コードの確認と、場所ごとのコンテナの数 |
| `GET /api/boxes?code=&at=` | その場所のコンテナの一覧 |
| `POST /api/boxes/move` | コンテナを動かす（駅 → トラック、トラック → 駅、トラック → 届いた） |
| `POST /api/factory/load` | 工場でコンテナを積む |
| `POST /api/train/run` | 貨物列車が走る（駅のコンテナを山ノ口へ、帰りの荷物を駅へ） |

- 使いすぎの制限：10 分あたり、コードを作るのは場所ごとに 10 回、呼び出しはコードごとに 240 回。
- 表は最初の呼び出しで作る（`CREATE TABLE IF NOT EXISTS`）。
- D1（`TRUCK_DB`）を作るまでは、呼べないのでトラックは端末の中の仮のコンテナで動く。

## 7. 確かめる用の URL

- `?mode=truck&auto&job=toStation&autopilot=8`：トラックが駅へ運ぶ依頼を自動で走る。
- `?mode=train&route=freight&auto&autodrive=8`：貨物列車を自動運転で速く進める。

## 9. 決まりごと

- 会社・町・路線・コンテナの会社名とマークはすべて架空。
- テクスチャと 3D モデルの素材は Poly Haven（CC0）。それ以外の絵は Canvas で描く独自のもの。
- 音はすべてその場で合成する（音の素材ファイルを使わない）。
