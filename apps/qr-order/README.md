# QR オーダー（店頭 QR 注文・事前決済）

店頭の QR コードを読み取り → 商品を選択 → クレジットカード / Apple Pay / Google Pay / Link / PayPay で決済すると購入が完了する（スタッフによる受け渡し操作はなし）、という流れのアプリです。

- アプリ: Cloudflare Workers（`src/index.ts`）+ 静的アセット（`public/`）
- データベース: Cloudflare D1（`migrations/`）
- 決済: Stripe（カード（JCB ほか）/ Apple Pay / Google Pay / Link / PayPay。表示される手段は Stripe ダッシュボードの「決済手段」の設定に従う。カード情報は当システムを通過・保存しません）

## 画面

| URL | 用途 |
| --- | --- |
| `/` | 公式サイト（サービス紹介）：お客様の使い方、特長、お店向けの機能、導入の流れ、よくある質問、導入のご相談。`public/index.html` と `public/site.css`。お問い合わせ先は【】の箇所を書き換える |
| `/wiki` | 開ける画面（パス）の一覧（`src/wiki.html`）。開くたびにパスキーでの本人確認を求める（ログイン中でも、確認から 5 分を過ぎていればログイン画面で確認し直し、確認後に戻る）。管理画面の上部「ページ一覧」から開ける |
| `/esl/<商品ID>.jpg`、`/p/<商品ID>` | 電子棚札（SoluM ST-GR29000、OpenEPaperLink）に表示する画像（296×128、商品の QR・商品名・価格）と、棚札の QR に入れる短いアドレス。設置の手順は [docs/esl-setup.md](docs/esl-setup.md) |
| `/s/<店舗ID>` | お客様のカート・決済画面。商品 QR または商品のバーコード（JAN）をカメラで読み取るとカートに入る |
| `/order/<注文ID>` | 決済後の購入の証明（注文番号・ご利用明細） |
| `/staff` | 店舗管理（PC・スマホ対応）：注文の確認、年齢確認、返金（全額・一部）、商品の登録（バーコード読み取り対応）・編集・削除・有効/無効・商品 QR、店舗 QR、スタッフ管理。個人別アカウントでログイン（`/staff/login`） |
| `/guide/customer`、`/guide/staff` | 画面のスクリーンショット付きの使い方ガイド（お客様用・スタッフ用）。印刷にも対応。スタッフ用（`src/guide-staff.html`）は管理画面にログインしている場合だけ表示し、未ログインならログイン画面へ移ってログイン後に戻る |
| `/legal/*` | 特定商取引法に基づく表記、利用規約、プライバシーポリシー |

商品を渡してよいのは **スタッフ画面に「支払済」と出ている注文だけ** です。支払済への変更は、Stripe で決済成功と金額一致をサーバー側で確認できた場合にのみ行われます。

## セットアップ

```bash
npm install
npx wrangler login
npx wrangler d1 create qr-order        # 出力の database_id を wrangler.jsonc に記入
npm run db:migrate:remote
npm run db:seed:remote                 # サンプル。seed.sql を実際の店舗・商品に書き換えてから
npx wrangler secret put STRIPE_SECRET_KEY
npx wrangler secret put STRIPE_PUBLISHABLE_KEY
npx wrangler secret put STRIPE_WEBHOOK_SECRET
npx wrangler secret put RESEND_API_KEY
npx wrangler secret put OWNER_EMAIL
npx wrangler secret put MAIL_FROM
npm run deploy
```

Stripe 側の設定:

1. ダッシュボードの「決済手段」でカード / Apple Pay / Google Pay / Link / PayPay を有効化し、公開ドメインを「支払い方法のドメイン」に登録（Apple Pay に必須）。
2. Webhook エンドポイント `https://<ドメイン>/api/stripe/webhook` を追加し、イベント `payment_intent.succeeded` を選択。署名シークレットを `STRIPE_WEBHOOK_SECRET` に設定。
3. まずテストキー（`sk_test_` / `pk_test_`）で実機確認してから本番キーに切り替え。

ローカル開発は `.dev.vars.example` を `.dev.vars` にコピーし、`npm run db:migrate:local && npm run db:seed:local && npm run dev`。

## 運用に関する仕組み

- **ログイン**: パスキーのみ（パスワードなし）。初回は `/staff/setup` でメールアドレスを入力し、メールで届く 6 桁の確認コード（10 分有効・5 回まで）で本人確認をしてからパスキーを登録する。最初の管理者は変数 `OWNER_EMAIL` のアドレス。以後のスタッフは管理者が「スタッフ」タブでメールアドレスと権限を登録する。端末紛失時は管理者が「再セットアップ」を押す。唯一の管理者が端末を失った場合は、Cloudflare で変数 `OWNER_RECOVERY=1` を一時的に設定すると `OWNER_EMAIL` で再セットアップできる（済んだら削除）。
- **購入完了メール**: お客様が注文時にメールアドレスを入力した場合（任意）、支払い完了時に注文番号と明細を送る。メールのリンクには合言葉（`?m=`）が付く。アドレスは返品・交換の受付メール用に申込期限の翌日まで保持して消去。失敗した場合は 1 時間ごとに再送し、24 時間で消去。
- **バーコード下の数字の読み取り**: バーコードの線が読めないとき、下に印字された数字を文字認識（Tesseract、`public/vendor/tesseract/` に同梱）で読む。認識は端末内で行い、チェックデジットが合う番号だけを採用する。初回のみ約 7MB の読み込みが発生する。
- **バーコードからの商品名入力**: 商品登録でバーコードを読み取ると、Open Food Facts（食品・飲料の公開データベース、登録不要）を調べて商品名を入力する。シークレット `YAHOO_CLIENT_ID`（Yahoo!デベロッパーネットワークで発行）を設定すると、Yahoo!ショッピングの商品検索も使い、食品以外も引ける。外部へ送るのはバーコードの数字のみ。
- **メール送信**: Resend を使用。シークレット `RESEND_API_KEY` と、差出人アドレスの変数 `MAIL_FROM` が必要。
- **注文作成の制限**: 同じ接続元から 5 分間に 30 回まで。シークレット `TURNSTILE_SITE_KEY` と `TURNSTILE_SECRET_KEY`（Cloudflare ダッシュボードの Turnstile で作成）を両方設定すると、注文時に Turnstile の確認を必須にする。
- **年齢確認商品**: 商品に「年齢確認が必要」を付けると、お客様は 20 歳以上の申告が必要になる。支払い後、注文は「年齢確認待ち」として管理画面の上部とお客様の画面に表示され、スタッフが「年齢を確認した」を押すと解除される。確認できない場合は返金する。
- **返金**: 管理者のみ。金額を指定して一部返金でき、全額を返金し終えると「返金済」になる。
- **自動整理（1時間ごと）**: 未払いのまま 24 時間たった注文は、Stripe 側の支払いを取り消したうえで削除。支払済の注文は既定で約 8 年（`ORDER_RETENTION_DAYS` で変更可）保存して削除。
- **QR コードの定期更新**: 管理画面の「店舗 QR」で店舗ごとに間隔（1 分〜1 日、既定は更新しない）を選ぶ。有効にすると店舗 QR・商品 QR の URL に時間で変わる合言葉が入り、切り替わり後は 1 つ前までが有効。有効な QR を読み取った端末に約 3 時間有効な入店確認を発行し、それがない端末からの注文は拒否する。印刷した QR は使えなくなるため、`/staff/display?store=<店舗ID>`（表示専用画面）などに映して使う。商品のバーコード（JAN）は影響を受けない。
- **ホーム画面への追加（PWA）**: スタッフ用（`/staff`、アプリ名「店舗管理」）と、お客様用（店舗ごとの注文画面）をホーム画面に追加してアプリのように起動できる。サービスワーカー（`public/sw.js`）は通信できないときの案内を出すだけで、画面やプログラムは保存しない。
- **お問い合わせチャット**: お客様は購入の証明の画面、または返品・交換の画面から `/contact/<店舗ID>?order=<注文ID>` を開き、その注文についてメッセージを送る（注文は選ばず、開いた元の画面の注文に決まる。やり取りは注文ごとに 1 つ）。店舗側は LINE 公式アカウント（Messaging API）で受け取り、リプライで返信するとお客様の画面に届く。管理画面の「問い合わせ」からも確認・返信できる。やり取りは 90 日で消去。
  - 設定：シークレット `LINE_CHANNEL_ACCESS_TOKEN`、`LINE_CHANNEL_SECRET`。LINE Developers の Webhook URL に `https://<サイト>/api/line/webhook` を設定し、Webhook の利用をオンにする。
  - 通知先の登録：管理画面の「問い合わせ」で連携コードを発行し、LINE のトークで「連携 123456」と送る。
- **返品・交換**: 購入完了メールの「返品・交換を申し込む」ボタン（購入の証明の画面からも可）で `/return/<注文ID>` を開く。お支払いから `RETURN_WINDOW_DAYS`（既定 7）日以内、商品・理由・説明・写真（2〜5 枚、全体は必須。端末で縮小・再保存して位置情報を除去）を送る。管理画面の「返品」で、管理者が承認（返金/交換）・却下を決め、お客様が商品を持参したら「商品を回収して完了」で返金する。写真は D1 に保存し、完了・却下から 90 日で消去。申し込みは LINE にも通知される。購入完了メールを送っていれば、同じ宛先に「返品・交換の受付メール」を送り、合言葉を新しくして、それより前のメールのリンクを無効にする（開くと「このメールのリンクは使えません」と表示）。
- **問い合わせの注文選択**: `/contact/<店舗ID>` で、この端末で購入した注文（端末内に保存した一覧）から選べる。選ばなくても送れる。
- **位置情報（GPS）**: お支払いと返品・交換の申し込みでは、端末の現在地の取得が必須（`public/geo.js`）。サーバーは店舗からの距離と測位の誤差だけを保存する。管理画面の「店舗 QR」で、地図（Leaflet + OpenStreetMap。住所検索は Nominatim）・地図アプリの共有リンク（短縮リンクはサーバーで展開）・座標の貼り付け・現在地のいずれかで店舗の位置と範囲（既定 200m）を登録すると、範囲＋誤差の外からの注文を拒否する。誤差 1km 超の位置は受け付けない。
- **注文番号**: 日本時間の日付が変わると 1 から振り直す。

`npm test` で、機能テストと画面テストを自動で実行します（テスト専用のデータベースと、決済・メールの代わりのサーバーを使うので、本番には影響しません）。`npm run report` で、結果からテスト結果報告書 [docs/test-report.md](docs/test-report.md) を作り直します。詳しくは [tests/README.md](tests/README.md)。

## 法令対応

実装済み:

- **特定商取引法**: 表記ページ、および決済直前の最終確認画面に 分量・価格・支払方法と時期・引渡時期・キャンセル条件 を表示
- **消費税法（総額表示・インボイス）**: 価格は税込表示。明細に取引日時・品目・軽減税率対象の表示・税率ごとの合計と消費税額・登録番号（`stores.invoice_number`）を表示
- **割賦販売法（カード情報の非保持）**: カード情報は Stripe が直接取得。サーバー・DB には保存されない
- **個人情報保護法 / 電気通信事業法（外部送信規律）**: 会員登録なし・氏名や連絡先は取得しない。プライバシーポリシーに Stripe / Cloudflare への送信と外国での取扱いを記載
- **資金決済法**: 前払式のポイントや残高は持たないため対象外の設計

公開前に事業者側で必要な作業:

- `public/legal/` 内の黄色い【】箇所（事業者名・住所・連絡先など）を記入
- 適格請求書発行事業者の場合は `stores.invoice_number` に登録番号（T+13桁）を設定
- 酒類・たばこ等の年齢確認が必要な商品、医薬品等の許認可が必要な商品はこのアプリでは扱わない（年齢確認機能なし）
- 店内飲食（10%）と持ち帰り（8%）が混在する業態では税率の扱いを別途設計する
- 法定表記・規約の文面は雛形です。公開前に弁護士・税理士等の確認を受けてください
